## 測試步驟

1. **重新安裝**：`npm ci` 先刪除 `node_modules`，再完全照 lockfile 安裝。
2. **安全檢查**：`npm audit`、`npm audit signatures`。
3. **靜態檢查與單元測試**：`npm run lint`、`npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`。
4. **實際誤差量測**：測試只斷言「低於門檻」，所以另外量測實際的誤差數值。
5. **E2E 與效能**：`npm run e2e`（在 production build 上執行），效能測試另外重複 3 輪。
6. **介面驗收檢查**：撰寫一次性的 Playwright 腳本，在瀏覽器中逐項驗證和畫面有關的驗收標準，證據截圖存在 [`docs/test-report/`](test-report/)。
7. **交付物檢查**：`npm run dev` 能否啟動、CI 狀態、lockfile、外部套件、README 章節。

## 發現的問題

### 問題 1：E2E 輔助函式在某些電路會等到逾時（已修正）

- **現象**：`e2e/helpers.ts` 的 `openCircuit()` 會等最後一個元件變成「可見」。當最後一個元件是導線時，Playwright 會把 SVG `<g>` 判定為不可見，導致逾時。
- **影響**：只影響測試程式，不影響產品。原本的效能測試碰巧沒觸發，是因為它的最後一個元件是電阻。
- **處理**：改成只等元件出現在 DOM 中（`state: 'attached'`），已隨本報告一起 commit。

### 問題 2：同一分頁貼上分享連結時，電路不會切換（待決定）

- **重現步驟**：開啟 App → 把另一個電路的分享連結貼到**同一分頁**的網址列 → 按 Enter → 畫面仍然是原本的電路。
- **原因**：兩個網址只差在 `#` 後面，瀏覽器會視為同頁跳轉，不會重新載入。而 App 只在啟動時讀取一次網址中的電路。
- **影響**：低。在新分頁開啟、或從聊天軟體點連結（通常會開新分頁）都正常，驗收情境也已驗證通過。但老師在課堂上直接貼到現有分頁時，可能會以為連結壞了。
- **建議修正**：監聽 `hashchange` 事件，網址變更時重新載入電路，再加一個 E2E 測試。預估改動不到 20 行。

## 其他觀察（不影響驗收）
