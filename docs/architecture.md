## 2. 整體架構

### 2.1 分層與依賴方向

```
┌────────────────────────── ui/ (React) ──────────────────────────┐
│ App · Toolbar · CircuitCanvas(SVG) · ElementView · PropertyPanel │
│ DiagnosticsPanel · PredictionPanel · ExamplesMenu                │
└───────┬───────────────┬──────────────────┬───────────────────────┘
        │               │                  │
   editor/          teaching/            io/
   reducer          prediction           json · share-link
   history          examples             png-export · validate
        │               │                  │
        └───────┬───────┴──────────────────┘
                ▼
            solver/  ──────────►  model/
     (純 TS、無 DOM、無 React)     (型別、幾何、元件定義)
```

- **solver/ 與 model/ 不依賴 React 與 DOM**：可以在 Vitest（Node）中直接做大量測試，包含性質測試。
- **求解結果是衍生資料**：`result = solve(circuit)`，不存進 state。Undo 只需還原 `circuit`，結果自然相同。
- 不引入狀態管理套件：`useReducer` + Context 就足夠。

### 2.2 目錄結構

## 3. 資料模型

```ts
type ElementKind = 'battery' | 'resistor' | 'bulb' | 'switch' | 'wire' | 'ammeter' | 'voltmeter';

interface Point {
  x: number;
  y: number;
} // 格點座標，0..60 × 0..40 的整數

interface ElementBase {
  id: string; // 穩定 id，存檔與分享時保留
  kind: ElementKind;
  a: Point; // 端點 A
  b: Point; // 端點 B（電池的 b 為正極）
}

type Element =
  | (ElementBase & { kind: 'battery'; emf: number; internalR: number })
  | (ElementBase & { kind: 'resistor' | 'bulb'; resistance: number })
  | (ElementBase & { kind: 'switch'; closed: boolean })
  | (ElementBase & { kind: 'wire' | 'ammeter' | 'voltmeter' });

interface Circuit {
  version: 1;
  elements: Element[];
}
```

**設計決定：所有元件都只用兩個端點表示。**

- 一般元件固定長度 **2 格**，以中點旋轉 90°，端點仍落在格點上。（長度 2 格 × 每格 20 px 時，元件長 40 px；投影時 SVG 會依視窗縮放）
- 導線可以是任意兩格點之間的直線（長度 ≥ 1），兩個端點可以分別拖曳。
- 「相連」只看端點：導線經過某格點的中間不算相連，跟需求一致，也讓網表建立很簡單。

**數值範圍（輸入驗證，也用來避免矩陣病態）：**

| 參數           | 範圍                  | 預設 |
| -------------- | --------------------- | ---- |
| 電阻、燈泡電阻 | 0.01 – 1,000,000 Ω    | 10 Ω |
| 電動勢         | 0 – 1,000 V           | 6 V  |
| 內電阻         | 0 – 1,000 Ω（允許 0） | 0 Ω  |

JSON 或分享連結讀進來的資料也會經過同一個驗證器，超出範圍的檔案會被拒絕並說明原因。

## 4. 求解器設計（核心）

### 4.1 管線

```
Circuit
  │ ① 建立格點節點
  ▼
點集合（每個用到的格點是一個點）
  │ ② 以 0 Ω 元件（導線、電流計、閉合開關）做 union-find → 超節點
  ▼
超節點圖（剩下：電阻、燈泡、電池；電壓計與斷開的開關不導電）
  │ ③ 拓樸檢查：懸空端點、理想電源短路、理想電源迴路
  │ ④ 依「導電元件」切成連通分量，每個分量各自建 MNA 並求解
  ▼
各超節點電位、各電池電流
  │ ⑤ 在超節點內部分配 0 Ω 元件的電流
  │ ⑥ 計算各元件 I、V、P、電錶讀數；電壓計「串聯」判定
  │ ⑦ 安全網：所有數值必須是有限值，否則該分量改標錯誤
  ▼
SolveResult { elements: 每個元件的結果或 null, diagnostics: Diagnostic[] }
```

### 4.2 理想元件怎麼處理

| 元件                   | 模型             | 處理方式                                                                                 |
| ---------------------- | ---------------- | ---------------------------------------------------------------------------------------- |
| 導線、閉合開關、電流計 | 0 Ω              | **縮合**：兩端併成同一個超節點，不進矩陣。電流事後由 ⑤ 算出。                            |
| 電壓計、斷開開關       | ∞ Ω              | **不蓋章（not stamped）**：不進矩陣。讀數 = 兩端電位差。                                 |
| 電阻、燈泡             | R                | 標準電導蓋章 G = 1/R                                                                     |
| 電池（E, r）           | 電壓源串聯內電阻 | 增加一個電流未知數 I，支路方程式 `V₊ − V₋ + r·I = E`；r = 0 時就是理想電壓源，同一套公式 |

**為什麼縮合 0 Ω 元件，而不把它們當成 0 V 電壓源？**
當成 0 V 電壓源時，學生隨手多畫一條平行導線，就會形成「電壓源迴路」，矩陣變成奇異。縮合之後矩陣只剩電阻與電池，比較小，也不會因為導線畫法出問題。

### 4.3 MNA 方程組（每個連通分量）

- 未知數：除了接地以外的 n−1 個超節點電位，加上 m 個電池電流。
- 接地：分量內 index 最小的超節點（排序固定，所以結果可重現）。
- 矩陣：
  - 電阻 R 接在 i、j：`A[i][i] += G, A[j][j] += G, A[i][j] −= G, A[j][i] −= G`
  - 電池 k（正極 p、負極 q）：`A[p][k] −= 1, A[q][k] += 1`（KCL）；`A[k][p] = 1, A[k][q] = −1, A[k][k] = r, b[k] = E`（支路方程式）
- 求解：自行實作**部分樞軸高斯消去法**。當樞軸絕對值小於相對門檻（例如 1e-12 × 矩陣尺度）時，回報「奇異」，不硬除。

**依連通分量分別求解的好處：**

1. 「兩組電路放在同一張畫布」與「分開求解」的結果在結構上就會相同（兩者建出一模一樣的子矩陣）。
2. 某一組接錯只會讓那一組顯示錯誤，另一組照常顯示結果，適合課堂對照。
3. 效能：區塊對角分解，成本從 O(N³) 降為 Σ O(nᵢ³)。

### 4.4 0 Ω 元件的電流分配（步驟 ⑤）

求出超節點電位後，每個格點從電阻、電池「注入」的電流都已知。超節點內部由 0 Ω 元件構成一張小圖，要找出滿足每個格點 KCL 的邊電流：

- 沒有迴路（樹狀）時，解是唯一的，例如電流計串聯在支路上，讀數就等於支路電流。
- 有迴路時（例如兩條導線並聯），物理上電流怎麼分是不確定的。做法是假設每條 0 Ω 邊的電阻都相同且極小，解 Laplacian 方程式 `L·φ = 注入電流`（同樣用自己的高斯消去法），邊電流取 `φa − φb`。這是**最小能量（最小範數）的分配**：並聯導線會平分電流，動畫看起來也自然。
- 這一步在每個格點上都滿足 KCL，所以「每個節點流入流出加總 < 1e-9 A」是以**格點**為單位來檢查的，比超節點更嚴格。

### 4.5 錯誤接法偵測

`Diagnostic = { severity: 'error' | 'warning', code, elementIds, message }`

- **error**：該連通分量無法得到合理結果。分量內所有元件顯示「—」，問題元件標紅。
- **warning**：有結果可以顯示，但接法不合理。問題元件標橘並附上說明。

| 代碼                     | 偵測方式                                                        | 等級                     | 學生看到的訊息（草稿）                                                             |
| ------------------------ | --------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------- |
| `BATTERY_SHORTED`        | 內電阻為 0 的電池，兩極落在同一個超節點，且路徑上只有導線或開關 | error                    | 電池的兩端被導線直接接在一起（短路），電流會大到無法計算。請在中間接上燈泡或電阻。 |
| `AMMETER_SHORTS_BATTERY` | 同上，但短路路徑上有電流計                                      | error                    | 電流計的電阻是 0，直接接在電池兩端會造成短路。電流計要和元件「串聯」。             |
| `CONFLICTING_SOURCES`    | 理想電池在超節點圖上形成迴路，且迴路電動勢總和 ≠ 0              | error                    | 兩個電壓不同的電池直接並聯，電壓互相矛盾，無法計算。                               |
| `SOURCE_LOOP`            | 理想電池形成迴路，電動勢一致，但不是單純的同兩點並聯            | error                    | 這幾個電池接成一圈，無法決定各自的電流。請替電池設定內電阻。                       |
| `SHORT_CIRCUIT_WARNING`  | 內電阻大於 0 的電池被短路（有解，I = E/r）                      | warning                  | 電池被短路了，電流非常大，實際上電池會發燙。                                       |
| `DANGLING`               | 元件的某個端點所在格點沒有其他端點                              | warning                  | 這個元件有一端沒有接上，所以不會有電流通過。                                       |
| `VOLTMETER_UNCONNECTED`  | 電壓計兩端不在同一個導電連通分量（含懸空）                      | warning（讀數顯示「—」） | 電壓計有一端沒有接到電路上，無法量測。                                             |
| `VOLTMETER_IN_SERIES`    | 見 4.6                                                          | warning                  | 電壓計應該「並聯」在要量測的元件兩端；串聯在電路中會讓電流幾乎無法流動。           |
| `SINGULAR`               | 安全網：高斯消去法遇到奇異矩陣，或結果出現非有限值              | error                    | 這個電路的接法無法計算出合理的結果，請檢查接線。                                   |

理想電源迴路是用 union-find 在拓樸階段偵測的，所以正常情況下不會走到 `SINGULAR`。`SINGULAR` 只是最後一道防線。

**特例：電動勢相同、內電阻為 0 的電池並聯（國中課本常見的「電池並聯」）。** 物理上合理，只是各電池分到的電流不確定。
→ **決定**：兩個電池接在同一對超節點、電動勢一致時，合併成一個電壓源來求解，再把電流平分給各電池。其他形狀的一致迴路才報 `SOURCE_LOOP`。

### 4.6 「電壓計串聯」的判定（啟發式）

拓樸上，「並聯量測」和「串聯在迴路中」都會讓電壓計兩端之間存在導電路徑，所以單看拓樸分不出來。改用求解結果判斷：

> 電壓計讀數不為 0（|V| > 1e-9），**而且**它至少有一個端點，除了電壓計本身以外，所接的導電元件都沒有電流。也就是說，電流原本該經過電壓計，卻被它擋住了。

- 例外：電壓計與某個斷開的開關接在同一對超節點上（量測開關兩端，課本也有這種用法）時，不判定為串聯。
- 讀數仍然照常顯示（理想電壓計串聯時，讀數≈電源電壓，這本身也有教學意義），同時標示 warning。
- 已知限制：屬於啟發式判斷，會寫進 README 的「已知限制」。

### 4.7 元件結果的定義

- 電流 I：從端點 a 流向 b 為正；畫面用箭頭表示方向。
- 電壓：`V(a) − V(b)`，畫面顯示絕對值並標出 +／− 極。
- 功率：電阻與燈泡為 `I²R`；電池顯示「提供功率 `E·I`」與「內電阻消耗 `I²r`」。
- 功率守恆檢查：`Σ 電池 E·I = Σ I²R + Σ I²r`。

### 4.8 數值輸出

所有顯示用的數字都經過 `format.ts`：固定 3 位小數，非有限值一律顯示「—」。另外有測試確保 UI 不會出現 `NaN`／`Infinity` 字串（雙重防線）。

## 5. 編輯器與狀態管理

```ts
interface EditorState {
  circuit: Circuit;
  history: { past: Circuit[]; future: Circuit[] }; // 上限 100 步（需求是 ≥ 50）
  selection: string | null;
  tool: 'select' | ElementKind;
  prediction: PredictionState | null;
}
```

- 所有編輯動作（add / move / rotate / delete / setValue / toggleSwitch / loadCircuit）都是 reducer 中的**純函式**，可以直接做單元測試。
- 拖曳過程使用暫存狀態，**放開滑鼠時才寫入歷史**；數值欄位在 Enter／失焦時寫入（輸入過程即時預覽重算）。
- Circuit 是 immutable，歷史快照共用未修改的元件物件，100 步 × 200 元件的記憶體可以忽略。
- 「復原後結果完全相同」的保證來源：`solve` 是純函式，元件順序與 id 固定 → 同一個 Circuit 一定得到位元級相同的結果。

**互動設計：**

| 操作       | 方式                                                       |
| ---------- | ---------------------------------------------------------- |
| 放置元件   | 左側工具列選元件 → 點畫布                                  |
| 畫導線     | 導線工具：從格點按住拖到另一個格點                         |
| 選取／移動 | 點擊選取；拖曳本體移動（吸附格點）；拖曳導線端點可改變形狀 |
| 旋轉／刪除 | `R` 鍵或按鈕／`Delete` 鍵或按鈕                            |
| 開關       | 點一下切換（移動距離低於門檻算點擊，否則算拖曳）           |
| 改數值     | 右側屬性面板                                               |
| Undo/Redo  | `Ctrl+Z`／`Ctrl+Shift+Z`、`Ctrl+Y`，以及按鈕               |

## 6. 呈現層

- **SVG** 畫布，`viewBox` 固定為 60 × 40 格，依視窗等比縮放，適合投影。
- 每個元件是 `React.memo` 元件，props 只放自己的元素資料與結果。改一個電阻值時，只有結果真的改變的元件會重繪。
- **流動點動畫**：導線使用 `stroke-dasharray` 搭配 CSS `stroke-dashoffset` 動畫，方向由 `animation-direction` 決定，速度依 |I| 的對數刻度換算成動畫週期。每一幀都不需要執行 JavaScript，200 個元件也不會拖慢主執行緒。
- **燈泡亮度**：使用**絕對刻度**（對數，例如 0.01 W 到 100 W 對應到 0 到 1）。不依畫布中的最大值正規化，這樣串聯組和並聯組放在同一張畫布時，亮度才能公平比較。
- **數值標籤**：預設在元件旁顯示 I／V／P，可以整體切換開關以免畫面雜亂。選取元件時，屬性面板會顯示完整數值。
- 電流計與電壓計在錶面上直接顯示讀數。

## 7. 教學功能

### 7.1 預測模式

1. 老師按「預測模式」→ 依序點選一個燈泡與一個開關。
2. 學生選擇「變亮／變暗／不變」。
3. 按「切換開關」→ 系統計算切換前後的燈泡功率 P₀、P₁。
4. 判定：`|P₁ − P₀| ≤ max(1e-9 W, 1e-6 × max(P₀, P₁))` 視為「不變」，否則依正負判斷變亮或變暗。
5. 顯示「預測正確／錯誤」與前後功率。若切換前後任一狀態有 error，顯示「這個電路有錯誤接法，無法判斷」。

判定邏輯 `judgePrediction(p0, p1)` 是純函式，有獨立測試。

### 7.2 內建範例（10 個）

1. 串聯燈泡（12 V、4 Ω + 8 Ω）
2. 並聯燈泡（6 V、3 Ω ∥ 6 Ω）
3. 串並聯混合
4. 惠斯登電橋（平衡）＋ 檢流用電流計
5. 惠斯登電橋（不平衡）
6. 電池內電阻造成端電壓下降（9 V、r = 1 Ω、8 Ω 負載，附電壓計）
7. 串聯 vs 並聯對照（同一畫布兩組電路）
8. 電流計與電壓計的正確接法
9. 開關控制並聯支路（預測模式示範）
10. 錯誤接法示範（短路，展示錯誤提示）

每個範例都有測試：載入後無 error，關鍵數值符合手算值。

## 8. 儲存與分享

- **JSON**：`{ "app": "circuitlab-jr", "version": 1, "elements": [...] }`。下載使用 Blob，讀檔使用 `<input type=file>`。讀入時經過 `validate.ts`（手寫型別守衛，不引入 schema 套件），錯誤會說明是哪一欄有問題。
- **分享連結**：JSON → 瀏覽器原生 `CompressionStream('deflate-raw')` 壓縮 → base64url → 放在網址 **hash**（`#c=…`）。
  - 不需要額外套件；hash 不會送到伺服器，也適合 GitHub Pages 這類靜態主機。
  - 200 個元件壓縮後約數 KB，網址長度沒有問題。
- **PNG**：複製 SVG → 內嵌必要樣式 → 繪製到 `<canvas>` → `toBlob`。匯出的是靜態畫面（不含動畫）。
- 來回轉換測試：存檔 → 讀檔、編碼 → 解碼後，`Circuit` 深度相等，`solve` 結果也深度相等。

## 9. 效能策略與量測

預估：200 個元件、單一大分量時，MNA 約 100 到 150 階，高斯消去約 1 百萬次浮點運算，在 JS 中約 1 到 5 ms。React 重繪受 memo 控制，主要成本在 SVG 屬性更新。

- 求解在主執行緒同步進行，不使用 Web Worker（測試比較簡單，預算也很充足）。如果量測結果不理想，再考慮對 0 Ω 樹狀結構先做葉節點剪枝。
- **量測**：
  - Vitest：求解器在 200 個元件 benchmark 電路上的耗時。
  - Playwright：載入 200 個元件的電路 → 程式化修改一個電阻值 → 用 `performance.mark` 從派送動作量到下一幀 `requestAnimationFrame` 之後，跑 20 次取 p95。結果寫進 README，並附上 Performance 面板截圖。

## 10. 測試策略

| 類別               | 內容                                                                                              | 預估數量  |
| ------------------ | ------------------------------------------------------------------------------------------------- | --------- |
| linalg             | 已知解、需要換列的零樞軸、奇異偵測、殘差檢查                                                      | 6         |
| netlist/topology   | 只有端點相連、旋轉後仍在格點、超節點縮合、連通分量                                                | 6         |
| 教科書電路         | 12 V 4+8；6 V 3∥6；電橋平衡／不平衡；9 V r = 1 端電壓                                             | 6         |
| 電錶               | 電流計讀數 = 支路電流；電壓計讀數 = 電位差；接上電壓計前後電流相同                                | 4         |
| 互不相連的兩組電路 | 合併求解 = 分開求解                                                                               | 2         |
| 錯誤接法           | 5 種指定接法 + 其他 diagnostic                                                                    | 9         |
| **性質測試**       | 固定種子、≥ 1,000 個隨機合法電路：KCL < 1e-9、功率守恆 < 1e-6、全為有限值、決定性、合併／分開等價 | 5         |
| editor             | reducer 各動作；60 步 Undo/Redo 後電路與結果完全相同                                              | 6         |
| io                 | JSON 來回、分享連結來回、壞檔被拒                                                                 | 5         |
| 預測模式           | 變亮／變暗／不變／錯誤                                                                            | 4         |
| 範例               | 每個範例載入且數值正確                                                                            | 10        |
| format             | 不輸出 NaN／Infinity                                                                              | 2         |
| **合計**           |                                                                                                   | **約 65** |

**性質測試的電路產生器：**

1. 隨機產生 2 到 12 個抽象節點，先用隨機生成樹保證連通，再加上額外的邊形成迴路。
2. 邊的種類隨機：電阻、燈泡、電池（r > 0 或 r = 0）、開關、電流計、導線、電壓計。
3. 「合法」的約束是在產生時用 union-find 保證：0 Ω 元件縮合後，理想電池不形成迴路、也不跨接在同一個超節點上。
4. **落到格點上**：每個抽象節點對應一個「匯流格點」，元件放在空位，再用導線把端點拉到匯流格點。這樣測試會走完整管線（包含網表建立與 0 Ω 電流分配），而不是只測矩陣。
5. 有 1/3 的案例會在同一張畫布上放兩個獨立電路，順便驗證「合併求解 = 分開求解」。

## 14. 已知限制（預計寫進 README）

- 「電壓計串聯」是啟發式判定（見 4.6）。
- 0 Ω 元件形成迴路時，電流採用平均分配（最小能量解）；這是理想化的假設。
- 只支援直流穩態與線性元件；燈泡電阻不隨溫度改變。
- 只支援桌機滑鼠操作；畫布大小固定。
